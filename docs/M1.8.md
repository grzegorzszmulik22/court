# M1.8 — Completeness and overhead

## What was built

- The load run (`TestC1_8_1`): 8 scripted agents in parallel, each
  interleaving tool calls with edit+commit pairs — 10,504 `tool.event`
  and 504 `world.commit` events. Every scripted step produced exactly
  one ledger event, compared against the script, not Court's counters.
- The latency harness (`TestC1_8_2`, MM1.4): 150 paired measurements of
  a hook post against a no-op endpoint on the same client; the paired
  difference cancels transport noise, p99 ≤ 50 ms.
- Kill/restart (`TestC1_8_3`): an agent runs 40 steps while the daemon
  is closed and rebuilt on the same store mid-run; the client retries
  through the gap, every acknowledged post is present, a byte-identical
  repost is deduped, and a post is durable in the ledger before its ack
  returns (the `ack-before-durable-write` sabotage flushes early and is
  caught here).
- `docs/M1-exit-review.md` answers the two questions of `00` §5 and
  names the weakest point of each.

## Check results

C1.8.1–C1.8.4 PASS. Sabotages: `retry-creates-duplicate-event` caught by
C1.8.1/C1.8.3; `ack-before-durable-write` caught by C1.8.3 (the patch
flushes the response before `emit`, so the ack-check sees a missing
event).
