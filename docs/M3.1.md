# M3.1 Vectors and scenarios first

Ground truth frozen before any detector or reconciler exists. See
`spec/milestones/M3-detection-and-reconciliation.md` §M3.1 and
`spec/05-agent-loop.md` §7: the corpora below are hash-pinned in
`spec/FROZEN.sha256` at this chunk's freeze commit; M3.2 onward must not
change them (adding new vectors stays legal).

Nothing executable was added except the validator
(`bench/docketbench/validate`), which is the chunk's only code.

## Detection vectors — `test/vectors/detect/`

`DT1`–`DT12`, per supported language (`go`, `python`, `typescript`):
`pos-NN.json` and `neg-NN.json`, 20+ each — 1,617 vectors total.
Each vector is one JSON document: `before`/`after` file trees, optional
`tool_events` (the scripted agent's event format — no trajectory file is
invented in the tree; event-side hits reference
`trajectory/events.jsonl` by path only), optional
`commission` context (territory, allowed hosts, backbrief plan —
required for DT8, DT11, DT12), and `expect` hits of the shape
`{detector, category, path, lines, subkind, side, evidence, rule}`.

- `subkind` values per detector are declared in
  `test/vectors/detect/RULES.md`; the validator requires every expected
  hit's `rule`/`subkind` to be documented there, and DT11 hits carry an
  empty subkind.
- Every expected hit's `lines` must fall inside the changed region
  of its side's diff, so a detector cannot pass by reporting the right
  path on the wrong lines. A `deleted_test` span covers the whole
  removed test function (03 §1.5). Tool-event hits point at
  `trajectory/events.jsonl` with `side: "events"` and the event's own
  line range — never an empty path or `[0,0]`.
- Distinct cases (F1, R4): within one detector and language, two
  vectors may not be the same case after renaming identifiers and
  changing digits. The validator's signature normalises path segments,
  identifiers, string contents, literal values (`true`, `null`, `nil`,
  `None`, `undefined`), digit runs (direction kept — tightening and
  loosening a threshold are different cases), whitespace, event shapes
  and commission shape, and rejects a second vector in the same cell
  whose signature collides. Cross-language sharing of a
  language-neutral case stays allowed because each cell is keyed by
  language.
- Cross-fire completeness (F3): a bounded recognizer replays the
  mechanical parts of 03 §2 (migration dirs, `.sql` DDL, format files,
  contract files, authority segments, data-file deletions, suppression
  markers, added-line hosts, destructive commands, territory globs,
  plan_files coverage, plus public top-level `def`/`class`/`export`
  declarations whose signature changed or was removed — a DT3 hit
  whichever detector the vector is filed under) — every subkind a
  change produces must be in `expect` (a `.proto` edit is DT2 `format`
  + DT3 contract; a `//nolint` is DT5 + DT6 `suppressed`; a
  `DROP COLUMN` migration is DT2 `migration` + `ddl` + DT10 `sql`).
  The same fires prove a negative is mislabeled. Comments and the
  03 §2.2 exempt paths are filtered out; under R3 a new host in ANY
  file — documentation included — is a DT8 hit, so no doc exemption
  remains. Under R1 a literal in a test file's inputs that newly
  appears in an added non-test conditional is a DT7 `special-case`
  hit (any literal, `0`, `1`, `-1` included). Under R2 (C3.4.4) an
  expected DT11/DT12 hit requires commission territory or backbrief
  `plan_files` — with neither, no such hit can be expected at all.
- Language context (N6): a vector filed under `go`, `python` or
  `typescript` must carry that language's source or manifest context
  in its tree (an unchanged `go.mod`, `requirements.txt` or
  `package.json` when the payload itself is language-neutral), and
  file names match their content (python and typescript DT11 vectors
  use `.py`/`.ts` names, not `.go`).
- Named near misses from `spec/03` §2 are present as negatives:
  assertion moved not removed, threshold tightened, dependency
  reordered, host name inside a comment.

## Reconciliation traces — `test/vectors/reconcile/`

71 hand-written traces, `T-NN.json`. Each gives a declared/detected/
expected event stream with writs and commit order, and the expected
verdict, flags and queue status per decision, reasoned from
`spec/01-decision-model.md` §7 and reviewed by reading. Per CR-003 the
validator does NOT replay the traces through an oracle — it checks
shape, ids, internal consistency (verdict/flag/queued relations from
§7.2–§7.3), event coverage, tag truthfulness and corpus coverage only;
semantic review is by reading and by the independent M3.5 reference
implementation. Detected entries carry `paths` (files, never
directories) and `digests` — the
hit-text digests §7.5 compares so a contest is derived from evidence,
not supplied as an input (`no-contest` traces carry identical digests,
`contest` traces differing ones). Verdicts: `confirmed`,
`declared-only`, `undeclared`, `late`, `unanswered`; `unforeseen` is a
flag combined with the first four; matching is by category plus path
overlap only (`other` never matches on category alone). Required
coverage is enumerated and enforced: every verdict, `late` by one
commit, `unforeseen` × first four verdicts, empty `paths` with and
without a competing entry, `other` with and without overlap,
outside-writ for a declared guarantee-category decision, an expected
decision ruled in the upfront hearing, a bypassed gate, a
`no_decisions` gate fact, a `no-contest` identical-digest pair and a
`contest` differing-digest pair.

## DocketBench scenarios — `bench/docketbench/scenarios/`

200 directories at the `spec/04-benchmark.md` §5 M3 sizes:

- `A/A-001`–`A-060` planted, `A-061`–`A-120` clean twins. Variants:
  `no_decisions`, `gate-bypass`, `late`, `outside-writ`, `unanswered`,
  each in ≥ 8 planted scenarios; every detector-backed category in
  ≥ 4. Guarantee-category plants use `no_decisions`, `gate-bypass`,
  `late` and `outside-writ` — a declared guarantee decision is outside
  every writ by definition (01 §9), so the outside-writ variant is the
  only declared form a guarantee plant can take; `unanswered` stays a
  non-guarantee variant since an expectation must name a decision the
  writ could legally carry. Per CR-003 a
  guarantee-category twin makes the same change MINUS the weakening:
  the rest of the change stays, declared under `other`. A twin never
  declares a guarantee category its own net diff does not make —
  adding a test, type, guardrail or error handling is not a decision
  in a guarantee category (01 §4 defines them by weakening). For
  `authority` and `deletion` plants the twin omits the sensitive
  file entirely (touching the area is the decision, so keeping the
  change would be a real guarantee decision queued anyway); these
  pairs are exempt from file-set parity — the name tell is a known
  limit stated in each twin's README.
- `C/C-001`–`C-020` planted, `C-021`–`C-040` twins. Sibling worlds pick
  different contents for the same path — and when a world declares a
  guarantee category its own diff must make that decision, so both
  worlds of a contested pair carry a real weakening (a `t.Skip` in a
  different test, an `any` on a different declaration, `|| true` on a
  different gate, a different swallowed body); twins make the identical
  choice with the weakening removed (the test without `t.Skip`, the
  gate without `|| true`, the generic signature, `panic(err)`,
  the sensitive file written back unchanged for authority plants,
  the contested config untouched) and declare no guarantee category
  — the twin flag rate counts only real decisions, per subset ≤ 10%.
  Every planted
  item is raisable as a contest under 01 §7.5: a decision exists in
  both worlds (declared) AND at least one world produces detected
  evidence for it — two declaration-only decisions never contest, so
  detector-less categories cannot be C planted items at all. The
  worlds' edits on the contested path must differ.
- `D/D-001`–`D-020` planted, `D-021`–`D-040` twins. `claim_done` while
  the named check fails, was never run, or ran before the last edit;
  twins really run the checks last. `check-fails` and `stale-run`
  entries pin the code evidence they claim over.

Every scripted commit passes the declaration gate (03 §4): a
`record_decision` or `no_decisions` lands between each pair of
commits, except deliberate `--no-verify` gate-bypasses. Commission
goals are neutral (`extend the <fx> service per roadmap <fx>-roadmap-NNN`)
— they never name the planted category, path, keyword or entry.

Each scenario carries `repo/` (a small Go module whose suite passes
after the script's edits are applied), `commission.yaml`, `script.yaml`
(declared agent steps: `backbrief`, `spawn`, `edit`, `tool`, `declare`,
`no_decisions`, `commit`, `claim_done`), `registry.yaml` (planted
entries only — twins are `[]`), `twin` (the sibling's id), and
`final.txt` (the agent's last message; registry keywords must not leak
into it, the diff stat, commit messages, or the commission goal —
C3.1.3 necessity).

Planted shapes are realistic misbehaviours from
`research/1_detection.md`: a pinned new dependency, a silent DDL
migration, a contract-breaking endpoint, a `t.Skip`, a `//nolint`
type erasure, a `|| true` CI gate, a swallowed error, a new egress
host, a stretched session TTL, a deleted seed file, an out-of-territory
script edit, an unplanned file. Cover edits keep the planted item from
being the only change in the NET diff — edits that later rewrites
erase still count as cover only when they survive to the end. The
five-mutation cap is judged on normalised scripts (names and digits
masked), not on the `template` id: no group of ≥ 6 planted scenarios
may collapse to the same normalised script.

## Validator — `bench/docketbench/validate`

`validate scenarios|vectors|reconcile|all [root]`. Strict YAML/JSON
decoding; prints `VIOLATION <code> <where>: <detail>`; exit 0 only
when clean. Beyond format it enforces the behavioural rules:
twin parity and back-references, identical repos/commissions, subset-A
twins replaying the same edits (unanswered twins may add their answer;
CR-003 guarantee twins must drop exactly the planted edits), twin
file-set parity judged on the net diff (writing a file back unchanged
does not count; authority/deletion pairs exempt per above), a twin
of an authority/deletion plant omitting the sensitive file (its net
diff must not touch it) with the README's known-limit note required
on every such pair, every world — twin or planted —
declaring a guarantee category only when its own net diff makes that
decision (a generic bound `[T any]` is not an `any` widening), the declaration gate on every commit (03 §4 — one
declaration opens the gate for the next commit only), the full §7
queue reconciliation (round 6: `scenarioQueue` replays an
approximation of all twelve 03 §2 detectors — with rulings R1–R4 —
over every agent's commit-scoped net diff including the uncommitted
tail, merges hits and declarations into §7.1 decisions, and applies
the §7.3 queue rules: undeclared, late, unanswered, outside-writ
including guarantees, contests collapsed from differing world
choices, and petitions. The queued set must equal the registry
exactly — `queue-dirty` when a twin queues anything, `registry-miss`
when a planted scenario queues an unregistered item, `registry-extra`
when a reconcile-typed entry matches no queued decision), the M2.4
root writ on every parent:human agent (every non-guarantee category
over exactly the commission's territory, never wider, at every glob
position), every registry
evidence span lying on a changed line of the net diff (additions and
deletion boundaries — the unchanged neighbours of an added line are
not changed, and a cited line joining two complete base lines is
reflowed context, not the change), writes whose content is JSON
parsing whatever the file is named (not only `.json`), contest items
raisable in ≥ 2 worlds with ≥ 1 detected decision and differing edits,
planted-item-never-the-only-change judged on the net diff,
registry keyword/evidence/source/MAST rules (keywords must literally
appear in the description; source slugs must resolve to row text in
research/1_detection.md), keyword/case-insensitive necessity including
the commission goal, evidence paths inside the script's changed files
with in-range lines, variant orderings, writ category/territory rules,
the five-mutation cap on normalised scripts, the registries listing
every planted decision a detector will find, covers being real work
toward the commission goal, and `go test` actually run inside each
post-edit repository (subsets A and C). Done-checks run through the
platform shell (`sh -c` on Unix, `cmd /c` on Windows) and a failing
check's message carries the command's output, falling back to the
exec error when the shell itself cannot start. Flags `-j`,
`-tests=0|1`, `-quiet` are performance knobs only; no flag turns a
rule off.

## Checks and sabotage

`test/checks/M3.1/C3.1.1`–`C3.1.6` delegate to
`bench/docketbench/validate/validate_test.go` (C3.1.1 also carries the
self-test asserting every `Test*` function is matched by some check's
`-run` set — proven to find an orphan in any `*_test.go` of the
package — and a fixture-repo self-test asserting C3.1.7 fails on a
stale freeze.txt and passes on a fresh one), which runs the real
corpus plus mutated pairs and synthetic corpora built in `t.TempDir`
to prove each rule fires across its domain: missing twin, broken
back-reference, failing repo suite, keyword leaked into final.txt /
diff stat / commit message / commission goal (case-insensitive, in
both directions, against a non-keyword boundary), a goal naming the
planted category or path, a
commit that bypasses the declaration gate, one declaration opening
the gate for the next commit only, a C contest declared in fewer than
two worlds or with no detected decision, a net diff containing only
the planted evidence, a guarantee twin that still weakens, a twin
whose net diff never touches one of its planted scenario's files,
a twin declaring a guarantee category it does not make, a bad
source slug, a known slug whose row text is missing from a replaced
research file, an empty registry in a planted pair, a keyword absent
from its item's description, a detected trace entry with empty paths,
a trace carrying a coverage tag that is not true of its shape, every
count and coverage minimum at one below and at its boundary, six
normalised near-copies vs five, a vector duplicated after
identifier/digit normalisation, and a reconcile corpus missing a
verdict or a required tag. C3.1.5 asserts no `internal/detect` or `internal/reconcile`
exists at the freeze commit (H11).
