# M1.2 — the ledger

`internal/ledger` implements the append-only, hash-chained ledger of
`spec/01` §11. One SQLite file (`modernc.org/sqlite`, `CGO_ENABLED=0`), WAL
mode, one `ledger` table plus derived tables rebuilt by replay.

## Envelope and canonical bytes

Every event is `{seq, prev, at, commission, actor, type, body}` plus a
sibling `hash`. Canonical bytes are RFC 8785 (JCS) of the envelope *without*
`hash`; `hash` is their SHA-256, hex. `prev` of event 0 is 64 zeroes; later
events carry the previous event's hash. Every envelope field feeds the hash
(`TestHashCoversEveryField`). `internal/ledger/jcs.go` implements JCS:
UTF-16-code-unit key order, minimal string escaping (raw U+007F+ unescaped,
lowercase `\uhhhh` under U+0020), ES6 number serialization. C1.2.1 proves it
against the upstream testdata corpus (input/output/outhex), the UTF-16 sort
edge, and the published sha256 of the first 10,000 ES6 numbers of the
deterministic test stream (`internal/ledger/testdata/rfc8785/`).

## Strict decoding

`internal/ledger/json.go` is a strict JSON parser: rejects duplicate keys,
lone surrogates, raw control characters, invalid UTF-8, trailing data.
`DecodeEnvelope` rejects unknown envelope fields, missing fields, bad types,
non-integer or out-of-range `seq`, non-hex `prev`/`hash`, malformed `at`
(`YYYY-MM-DDTHH:MM:SS.mmmZ`), bad `actor`, and unknown event `type`
(`TestStrictDecode`, `TestEnvelopeStrict`).

## Store and append

`Store.Append` allocates `seq` and `prev` *inside* `BEGIN IMMEDIATE`, so a
failed or crashed attempt never reuses a number and concurrent writers
serialize on the write lock (C1.2.3 runs two processes over one file). The
projector updates the derived tables in the same transaction, so the chain
and the derived state are always at the same point. A crash between write
and commit at any of 200 (point, seq) injections leaves a verifying ledger
and a retried append lands at the next seq (C1.2.4,
`COURT_LEDGER_FAULT=point[:seq]`).

`synchronous` is `NORMAL`: in WAL mode each commit's frames are written in
order, which is durable across process and OS crashes (what C1.2.4 kills).
`FULL` fsyncs every commit and measured ~220 events/s — under the MM1.5 bar
— while `NORMAL` measures ~6,800 events/s.

## Bodies and schemas

`internal/ledger/bodies.go` has the typed body of every event type of
`spec/01` §11.2; `api/schema/*.schema.json` are the shared JSON Schemas
(whole envelope + body) validated by `internal/ledger/schema.go` (the subset
in use: `type`, `enum`, `const`, `required`, `properties`,
`additionalProperties`, `pattern`, lengths/ranges, `items`, `minItems`,
`uniqueItems`, `anyOf`, `allOf`, `not`, `if`/`then`/`else`, local `$ref`).
C1.2.5 round-trips all 21 types, asserts the Go↔schema bijection and the
field-name bijection (`TestBodyFieldShapes`).

`tool.event` records only `tool`, `tool_use_id`, `input_digest`, the
permitted selected `fields` (`paths`, `command` ≤500 chars, `hosts`),
`outcome` and `reason` (denied only). File contents and command output are
never stored.

## CLI

`court ledger append|build|export|gen|loadgen|verify|mutate|goldens`,
`court replay <path>` (M1.3). `court version` prints the SQLite version.

## Sabotages

`prev-hashes-body-only` (C1.2.2 field-coverage test),
`seq-reused-after-failed-append` (C1.2.3 concurrent run),
`decoder-accepts-unknown-field` (C1.2.5 strict decode). All caught.
