# M1.1 — repository, toolchain, check tooling

Everything runs through `make`; the pinned toolchain lives in `.tools/`
(`make tools`, no root). Versions are in `tools/versions.env`.

## Targets

- `make check-<chunk>` runs `test/checks/<chunk>/<id>-*.sh` in name order and
  prints exactly `CHECK <id> PASS`, `CHECK <id> FAIL <reason>`,
  `CHECK <id> BLOCKED <reason>` or `CHECK <id> SKIP <reason>` per check on
  stdout; exit is non-zero unless all passed — SKIP, BLOCKED, FAIL, a
  `timeout` kill (`COURT_CHECK_TIMEOUT`, default 900s) and a check printing
  its own `CHECK <id>` line all fail the run. Check files exit 0 (PASS),
  77 (SKIP), 78 (BLOCKED) or anything else (FAIL); the first stderr line is
  the reason. `COURT_CHECKS_DIR` overrides `test/checks` (used to test the
  runner itself on temporary chunks).
- `make sabotage-<chunk>` applies each `test/sabotage/<chunk>/*.patch` to a
  scratch copy (never the working tree), runs the chunk's checks, and
  classifies each patch: `SABOTAGE <name> caught by <ids>` when at least one
  check printed a non-PASS line, `UNCAUGHT <patch>` when the inner run
  passed, `SABOTAGE <name> ERROR <why>` when the patch did not apply
  (`git apply`, no fuzz) or the inner run failed without any non-PASS CHECK
  line — an ERROR is never a catch. Output ends with `<n> uncaught`;
  exit is non-zero unless every patch applied and was caught. The inner run
  gets `COURT_CHECKS_DIR`, `COURT_SABOTAGE_DIR` and `COURT_CHECK_EXCLUDE`
  unset, so no check can be excluded from evaluation.
- `make regress` verifies `spec/FROZEN.sha256` and re-runs checks of every
  chunk marked DONE in `spec/PROGRESS.md` or `spec/progress/*.md`.
- `make lint` runs gofmt, `go vet`, `bash -n` on tracked scripts and the
  `spec/progress/*.md` row linter.
- `make clean` removes build artifacts only (never `.tools` or `evidence/`).
- `make sysinfo` prints the machine description used in measurement reports.

## Evidence

Every run writes `evidence/<chunk>/<UTC timestamp>/` with `output.log` (full
run output), `result.json` (`command`, `exit_code`, `duration_ms`,
`git_commit`, `started_at`) and `checks/<id>.log` per check. The folder named
in a progress row is committed.

## Frozen files

`spec/FROZEN.sha256` lists `spec/0*.md` and `spec/milestones/*.md` (frozen from
the start, `05` §7). `tools/frozen_verify.py` fails on a changed file, a
missing file, or an unlisted file matching a frozen pattern.

## Notes

- Go is downloaded from dl.google.com (sha256-pinned in `versions.env`).
- git and python3 have no upstream linux/arm64 binary build and there is no C
  compiler on the host, so `make tools` verifies the system versions meet the
  pinned floor and links them into `.tools/bin`.
- `CLAUDE_CODE_VERSION` is recorded from the public changelog only; nothing
  installs or runs it.
- `COURT_CHECK_EXCLUDE` (comma-separated ids) omits checks — used by the
  fresh-clone check to avoid re-running itself. Sabotage runs always clear
  it for the inner evaluation.
- `COURT_SABOTAGE_DIR` overrides `test/sabotage` so checks can feed the
  runner deliberately broken patches; `COURT_SABOTAGE_TIMEOUT` caps the
  inner run (default 600s).
