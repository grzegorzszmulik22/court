# M1.4 — worlds

`internal/world` implements the `World` interface of `spec/02` §3 on git
worktrees. One backend only; no repository copying, no merging (chunk denied
list).

## API

`world.Open(repoPath, dataDir, commission)` binds a repository to a Court
data directory and returns its root world. It refuses, with one sentence,
any repository that has a submodule (`.gitmodules`, a registered submodule,
or a gitlink in `HEAD`), because upstream marks multi-worktree submodule
support incomplete.

```go
type World interface {
    Fork(base Commit, name string) (World, error) // worktree on court/<commission>/<name>
    Diff(from, to Commit) (Changes, error)        // --numstat line counts
    Run(cmd []string, limits Limits) (Result, error)
    Commits() ([]Commit, error)                   // rev-list HEAD, newest first
    Discard() error                               // restores the repository exactly
}
```

`Fork` runs `git worktree add <dataDir>/worlds/<name> -b
court/<commission>/<name> <base>`; one branch per worktree is a git rule and
is relied on. `Discard` removes the worktree (`--force`), deletes the branch,
and drops its administrative files. It never deletes from the shared object
store: no scan can decide safely which loose objects are unreferenced while
sibling worlds stage and commit concurrently, and the spec only asks for
exact restore over the reachable set (H3). Objects the world created stay as
unreachable garbage until a gc runs after the commission (`gc.auto` is off
during it). On this git version `branch -D` rewrites `packed-refs` and
leaves a header-only file where none existed; `Discard` removes that residue
so the ref state is restored file for file.

`Run` executes a command in the world with the per-world git configuration in
its environment: `GIT_CONFIG_*` pairs set `core.hooksPath` to the data
directory's `hooks/` and `gc.auto=0` (automatic garbage collection is off
for the commission), plus `core.longpaths=true` on Windows. Repository
configuration is never written. `w.GitEnv()` exposes the same entries for
adapters to pass to agent processes.

`Result` reports a timeout distinctly (`TimedOut`, `ExitCode == -1`) from a
non-zero exit; the whole process tree is killed so grandchildren cannot hang
the call. The process handling is split by build tag (CR-001):
`runproc_posix.go` (`!windows`) puts the command in its own process group
and kills the group; `runproc_windows.go` kills the tree with
`taskkill /T /F /PID` plus `Process.Kill` — no Unix-only call exists outside
a build tag, which C1.4.8 proves on every host with `GOOS=windows go vet
./...` and `GOOS=windows go test -c -o /dev/null ./internal/world/`.

World roots are kept at most `world.MaxWorldRootLen` (200) characters:
`Open` refuses a data directory whose longest possible root
(`<dataDir>/worlds/<name>`) would exceed it, in one sentence naming the
limit, and `Fork` guards the computed root too. The limit is a stated,
tested bound — git for Windows refuses worktree roots longer than 260
characters even with `core.longpaths` (CR-001).

Ref-lock failures are retried internally and counted (`w.Retries()`),
never surfaced to the agent.

`w.Digest()` hashes every ref, every object id reachable from a ref
(`git rev-list --objects --all`) and the worktree list — the H3/MM1.3
measure: equal before `Fork` and after `Discard` iff the repository was
restored exactly. Unreachable objects cannot move it.

## Evidence

`make check-M1.4` covers C1.4.1–C1.4.8. C1.4.7 is `SKIPPED-ENV` here (no
Windows host); C1.4.8 passes on Linux — `GOOS=windows go vet ./...` and
`GOOS=windows go test -c -o /dev/null ./internal/world/`.

On a Windows host the C1.4.6 and C1.4.7 checks run under plain `go test`
(no bash, make or other Unix tooling):

```
go test ./internal/world -run '^TestC1_4_6_RunTimeout$' -count=1 -v
go test ./internal/world -run '^TestC1_4_7_WindowsLongPaths$' -count=1 -v
```

`make sabotage-M1.4` runs the five listed sabotages (including
`unix-only-call-in-shared-file`, which C1.4.8 catches by breaking the
Windows build) plus `discard-deletes-objects`, which stands in for the
unsafe deletion Discard must not do — C1.4.1's sibling-staged-blob case
catches it. The one `tools/` file this lane was permitted to change for
Windows is `tools/frozen_verify.py` (path-separator normalisation, with a
test at `test/tools/frozen_verify_sep_test.py`).
