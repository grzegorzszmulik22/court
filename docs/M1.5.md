# M1.5 — Scripted agent and the hook endpoint

## What was built

- `internal/daemon`: the daemon — sole ledger writer. Loopback-only listener on an
  OS-assigned port. Endpoints: `/hook/<token>`, `/gate`, `/mcp/<token>` (stub until
  M1.6), and an admin endpoint that registers a session and returns its hook/MCP/gate
  URLs. The token is the path identity: a post under an unknown token is refused and
  the refusal is journaled; a post carrying another session's `session_id` is refused
  rather than reattributed (`internal/daemon/hook.go`).
- Hook → `tool.event` mapping: `PreToolUse` parks a pending entry keyed on
  `tool_use_id`; `PostToolUse`/`PostToolUseFailure` completes it (or records
  standalone when no Pre was seen). Stored body: tool name, `tool_use_id`, SHA-256 of
  the canonical `tool_input`, outcome, reason, plus only selected fields per tool
  kind — file paths, the command line truncated to 500 characters, host names
  (`buildToolEvent`). No file contents, no command output.
- Subagent attribution: a payload carrying `agent_id` is attributed to
  `<agent>:<agent_id>`; the first such post emits `agent.started` for the child
  (`actorOf`).
- Deny policy: `internal/adapter/claude/policy.go` returns `"deny"` + reason for
  outward actions (web fetch/search, non-Court MCP tools, package publishing, cloud
  CLIs, network shells) and for paths inside the Court data directory — except the
  session's own world subtree; `..` escapes are normalized away before the test.
  Otherwise it abstains (`""`, `""`) so Claude's own permission mode decides.
- `/gate`: post-commit hook target. Each world gets a generated `post-commit` hook
  that posts the new HEAD; the daemon walks `git rev-list` from the last recorded
  commit (bounded at the session base the first time) and emits `world.commit`
  events in order, under a per-world lock.
- Append-before-ack: `emit` appends to the store under the request's own identity —
  `hook|<tool_use_id>` for hook posts — and only then writes the HTTP 200; a resent
  post returns the same deduped result without a second event, while a distinct
  post with identical content still records. Request identities are persisted in
  the store's `idem` table and rebuilt from the ledger on restart.
- `internal/adapter/scripted`: reads `script.yaml` (agents, steps: edit/write/
  command/tool-call/commit), executes them against a world via the harness, and posts
  hook payloads built from the recorded corpus (`templates.go`). Used by every M1.5
  check.
- `test/vectors/hooks/recorded/hooks/` is the payload-shape authority: every
  payload the adapter sends is one recorded post loaded as a template with values
  changed — never an invented field list (`BuildPayload` refuses a kind that was
  never recorded, and a `Set` on a field the recorded shape does not carry, or a
  value of a different JSON type). `tools/hook-fields.txt` stays as the field
  documentation the drift check compares the corpus against.
- `court daemon` / `court gate` subcommands in `cmd/court/main.go` (the gate hook
  prefers `court gate` over curl).

## Check results

C1.5.1–C1.5.6 PASS against the recorded corpus on this branch, including the
shape conformance test (every sendable payload kind equals its recorded post's
key set and value types at every depth). Sabotages: all three caught
(0 uncaught).

## Decisions worth noting

- The token is the sole identity of a post; `session_id` is consistency-checked,
  never used for lookup.
- Worlds live inside the data directory, so the data-dir deny rule exempts the
  session's own world and still denies `..` escapes.
- `gate` bounded its rev-list at the session base after the first post walked the
  whole repository history.
