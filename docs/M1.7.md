# M1.7 — Claude Code adapter

## What was built

`internal/adapter/claude/claude.go`: the live adapter of spec/02 §4.1.

- `Settings` / `MCPConfig` / `WriteConfig`: per-session `settings.json`
  (http hooks for every consumed event posting to `/hook/<token>`, plus
  `allowedHttpHookUrls`) and `mcp.json` (the single `court` http server),
  written under `<data-dir>/agents/<agent>/` — never the repository.
- `Start` launches `claude -p <prompt> --output-format stream-json
  --verbose --input-format stream-json --session-id <token> --settings
  <gen> --mcp-config <gen> --strict-mcp-config --permission-mode default`
  with the world as the process working directory (the tool has no
  working-directory flag). `Adapter.Bin` is the executable path so
  hermetic checks run a stand-in double (C1.7.3); the vendor SDK is not
  used.
- `Send` writes one SDKUserMessage JSON line to stdin; `Stop` closes
  stdin, waits up to 2 s for a clean exit, then kills.
- The outward-action deny policy (`policy.go`, wired in at M1.5) is
  evaluated by the daemon on every PreToolUse — the adapter only carries
  configuration.

## Outward deny list: coverage and the stated limit

`Policy.outwardCommand` is a scanner over the shell text, not an
interpreter. It denies every outward program and every publish pair of
the configured list wherever they can appear as a *command*:

- every segment separated by `;`, newline, `|`, `&`, `&&`, `||`;
- inside `$( )`, `` ` ``, `<( )`, `>( )` — quoted or not;
- inside subshells `( ... )` and groups `{ ...; }`;
- as the argument of a shell's `-c` (`bash -c`, `sh -c`, `dash`/`zsh`/
  `ksh`/`fish`/`pwsh`/`cmd /c`, clustered or attached: `sh -cX`, `sh -xc x`)
  — recursively, so `bash -c "sh -c 'git push'"` is denied;
- behind transparent wrappers (`timeout`, `nohup`, `xargs`, `exec`,
  `time`, `stdbuf`, `setsid`, `sudo`, `doas`, `command`, `env` — including
  `env -S`, `nice`, `busybox`, `strace`, `parallel`, `watch`, `chroot`,
  `taskset`, `unshare`, `nsenter`, `ionice`, `numactl`, `valgrind`,
  `ltrace`, `builtin`, `noglob`, `catchsegv`, `arch`), with per-wrapper
  option-argument tables (`sudo -u root curl`, `timeout -s 9 5 curl`,
  `xargs -I {} curl`);
- as an absolute or relative path (`/usr/bin/curl`, `./curl`,
  `C:\bin\curl.exe` — basename + `.exe` are normalized), and equally for
  wrappers, shells and `eval`/`find` themselves (`/usr/bin/sudo curl`,
  `./nohup ./curl`, `env /usr/bin/git push`, `/usr/bin/bash -c 'curl x'`);

- via `eval` (its arguments reparsed) and `find -exec/-ok`.

**Stated limit.** A scan of the command line can only see commands that
are in the line. It cannot see outward behaviour hidden inside an
interpreter, a file, or a stream. Examples that are *not* denied and are
accepted as the residual of a shell-text policy:

- `python -c 'import urllib.request; urllib.request.urlopen(...)'` —
  the outward action is inside Python code, not a shell command;
- `echo 'curl x' | sh`, `bash script.sh`, `sh <<EOF …`, `ssh host 'x'`
  payloads — command text arrives via stdin or a file;
- `make publish`, `ninja` — commands live in a recipe file;
- `xargs -a cmds.txt`, `at -f file`, `source ./cmds` — same file-content
  class;
- a program name smuggled through an unexpanded variable (`P=curl; $P x`)
  — the word is an expansion, not the program's name;
- `powershell -EncodedCommand <base64>` — the text is encoded.

The residual is why the deny list is one layer of confinement (spec/02
§4.1), not a sandbox: the ledger records every attempt either way.
