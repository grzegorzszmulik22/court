# M2.3 — The blind clerk

## Public behavior

`court commission` runs the blind clerk of spec/02 §7 after the
orchestrator's backbrief is in: a tool-less one-shot call that sees only
the commission — the request file written under the agent's state dir
holds `{commission, goal, schema}` and nothing from the orchestrator's
backbrief or the repository (C2.3.1).

Two hermetic drivers select the clerk:

- `--clerk <file>` replays a recorded output;
- `--clerk-cmd <command>` runs a command with the request JSON on stdin
  and takes stdout as the output.

With neither, no model is configured: the commission proceeds on the
orchestrator's list alone and prints a line saying so (C2.3.4).

The output parses as `{"expected_decisions":[...]}` (or a bare list)
under the backbrief schema. A valid list is recorded as
`backbrief.submitted` with actor `clerk` before anything reads it. An
invalid output is recorded as `backbrief.submitted` with `invalid: true`
and its raw output (every model output enters the ledger), the
commission proceeds on the orchestrator's list, and one line tells the
human (C2.3.3).

The orchestrator's first non-read write waits for the clerk event
(`await_clerk` on the session), so the clerk's list precedes it in the
ledger (C2.3.5).

`internal/recon.Compare` diffs the two expected-decision lists under
`01` §7.1 — same `category` plus path overlap or the empty-paths rule;
`other` matches only through paths; question text is never compared.
`internal/paths` decides glob `Match`, `Contains` and `Intersects` on
NFAs, not string prefixes.
