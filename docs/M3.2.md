# M3.2 — the declaration gate

Every commit in a Court world must be declared before it exists
(`spec/03-detection.md` §4). Court installs two git hooks through
`core.hooksPath`, in `<data-dir>/hooks`, outside every world:

- **pre-commit** asks the daemon's `POST /gate/pre` whether the committing
  agent has called `record_decision` or `no_decisions` since the previous
  commit in that world. If not, the commit fails with exactly:
  `Declare this commit's decisions with record_decision, or call no_decisions.`
- **post-commit** reports the new commit to `POST /gate`, which records
  `world.commit` with `gated: true` only when the pre-commit hook authorized
  that commit's parent and index tree. Any commit that arrived without the
  handshake is recorded `gated: false`; reconciliation then treats every hit
  in it as `undeclared` (`01` §7).

The window is per world and derived from ledger order: one declaration opens
one commit. Declarations are the agent tool `no_decisions` (records
`decision.none`) and `record_decision`; subagents share their session's
world. A daemon restart re-derives open windows from the ledger and keeps a
persisted pre-commit pass, so a commit authorized before the restart is
still gated after it.

Commits that bypass the hooks (`--no-verify`, or `core.hooksPath` pointed
elsewhere) still run the post-commit hook when git runs it; when no hook
runs at all, the daemon's head scanner records the commit at the next ledger
write, within one second, as `gated: false`.

The repository's own hooks are not replaced: Court's scripts run the
repository's `pre-commit`/`post-commit` (from the common git directory, or
the repository's configured `core.hooksPath`) after Court's own work. A
failing repository pre-commit still aborts the commit.

The hooks directory is inside the Court data directory, which the adapter's
deny policy refuses for file tools and for shell commands that name it; the
scripted agent's attempts are recorded as denied `tool.event`s.

Checks C3.2.1–C3.2.6 live in `test/checks/M3.2/` and drive real daemons,
real worktrees and the scripted agent. The extra check C3.2.7 is not a
substitute for them: it self-tests the daemon-leak barrier (a deliberately
live daemon must be reported, on Windows and Linux) and, on Windows, proves
that an unopenable-but-live process is not called gone and that detached
children cannot inherit the standard handles.
