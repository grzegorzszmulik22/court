# M1.3 — independent verification, replay, and mutation

M1.3 proves the ledger can be checked without trusting the Go
implementation: a second verifier written from the spec alone, a replay
that rebuilds derived state from events, and a seeded mutation suite where
both verifiers must agree on the error class.

## The Python reference verifier — `ref/python/refledger`

Written from `spec/01` §11; the only shared artifact is the JSON Schemas in
`api/schema/` (allowed by the lane rule). Standard library only — C1.3.4
audits its imports against `sys.stdlib_module_names` and runs it under
`python3 -I`. It implements:

- a strict JSON layer on `json.loads` (`object_pairs_hook` for duplicate
  keys, `parse_int`/`parse_float` keeping raw literals, `parse_constant`
  rejecting `NaN`/`Infinity`), plus explicit UTF-8 and lone-surrogate
  checks;
- RFC 8785 canonicalization, including the ES6 number layout driven from
  `repr()` digits — `--selftest` regenerates the published deterministic
  IEEE-754 stream and matches its published sha256 (10,000 lines);
- the §11.1 envelope rules and the same schema subset as the Go side;
- the same verdict classes (`ok io empty truncated json envelope seq prev
  hash schema`) and the same check order, so C1.3.1 can compare classes
  directly.

It reads both `.jsonl` exports and `.sqlite` ledgers (stdlib `sqlite3`,
row-for-row reserialization).

## `court replay`

`court replay <ledger>` verifies the chain, replays every event through the
projector into an in-memory database, and compares the result with the
stored derived tables row-for-row. It also recomputes every stored
`decision.reconciled` verdict — the M1 rule is single-source: declared →
`declared-only`, detected → `undeclared`, expected → `unanswered` once the
commission closes (`recomputedVerdict` in `internal/ledger/project.go`).
C1.3.3 runs an M1.8-shaped generated run (agents, backbriefs with expected
decisions, declared + detected decisions, reconciliations, phrasing,
rulings, claims, alarms) and requires replay to fail both when a stored
derived row is tampered and when a stored reconciled verdict lies.

## Mutation — `court ledger mutate`

Thirteen kinds: byte-flip, remove, swap, edit-seq, edit-prev, edit-at,
edit-commission, edit-actor, edit-type, edit-body, edit-body-fixchain
(body edit with the chain re-tied so only the schema verdict can catch
it), dup, truncate. `Mutate` retries until the Go verifier reports a
non-ok class, so every emitted mutant is detectable; C1.3.1 then requires
the Python verifier to report the *same* class on every mutant — 200
ledgers, 2,600 mutants, plus hand-crafted tail cases (corrupt last hash,
corrupt last prev, missing trailing newline, partial last line,
out-of-order first line) so tail-skipping and truncation-accepting
sabotages cannot stay green.

## Golden vectors — `test/vectors/ledger/`

Four generated ledgers (minimal, mixed, large, unicode edge-cases) verify
in both implementations (C1.3.2) and are hash-pinned in
`spec/FROZEN.sha256`. The SQLite read path is covered too: C1.3.2 builds a
scratch database from `golden-mixed.jsonl` and verifies it in both — a WAL
database is not a stable frozen artifact since readers checkpoint on
close.
