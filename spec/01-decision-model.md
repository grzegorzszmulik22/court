# 01. The decision model

Normative. Sections marked *(later)* define terms that M1 to M3 record but do not yet act on; their behaviour is specified after gate G1.

## 1. Terms

| Term | Meaning |
|---|---|
| **Commission** | One goal given by the human, with done-checks, territory and budgets |
| **Agent** | A running instance of an agent tool. An **orchestrator** may start **subagents**. Agents form a tree under the commission |
| **World** | An isolated copy of the repository where one agent works: a git worktree on its own branch |
| **Decision** | A choice between options that the goal did not settle. The unit Court records, reconciles and rules on |
| **Ruling** | The selection of one option for a decision, by an agent inside its writ, by a statute *(later)*, or by the human |
| **Assumption** | A decision an agent has acted on before it was ruled |
| **Writ** | What an agent may decide alone |
| **Ledger** | The single append-only record of everything above |

## 2. The governing rule: models are inputs, logic is deterministic

Court uses models in three places: the agents themselves, the blind clerk's expected-decision list, and the phrasing pass that turns a detector hit into a question. **Every model output enters the ledger as an event. Everything Court then does is a deterministic function of the ledger.** Replaying a ledger reproduces every reconciliation result, queue order and verdict exactly, with no model call.

This is what makes hermetic checks possible (`05` §11), and what makes a Court ledger auditable.

## 3. The decision record

```yaml
decision:
  id:            D<n>, unique in the commission
  commission:    id
  world:         id of the world it arose in (absent for expected decisions)
  agent:         id of the agent it is attributed to (absent for expected decisions)
  question:      one sentence
  category:      one of §4
  paths:         [repository paths the decision concerns]   # may be empty
  kind:          unclassified | fact | will                  # set by the clerk (later); unclassified until then
  sources:       subset of {declared, detected, expected}
  detector:      [detector ids that fired]                   # when detected
  options:       [{id, summary, world_ref?, evidence?}]      # at least the chosen one when declared or detected
  chosen:        option id the agent acted on, if any
  class:         reversible | irreversible                    # §8
  state:         §6
  recon:         §7 verdict
  assumes:       [decision ids this one rests on]             # (later)
  ruling:        {option, by: agent | statute | human, at, shown_sha256?}
```

Constraints:

- `question` is at most 200 characters and ends with a question mark.
- A decision with `sources` containing `declared` has `agent`, `world` and `chosen`.
- A decision whose only source is `expected` has no `agent`, `world` or `chosen`.
- `category` and `paths` are the only fields reconciliation matches on (§7). Free text is never matched.

## 4. Categories

One closed list, shared by agent declarations, the backbrief lists and the detectors (`03` §2 maps each detector to a category).

| Category | A decision about |
|---|---|
| `dependency` | adding, removing or changing a third-party dependency or its version |
| `schema` | the shape of stored data: tables, columns, migrations, serialised formats |
| `interface` | anything other code or users call: exported symbols, routes, command flags, configuration keys, wire formats |
| `test-strength` | removing, skipping or loosening a test or assertion |
| `type-strength` | loosening a type or silencing a type checker |
| `guardrail` | changing a check that guards the repository: lint rules, CI steps, coverage or quality thresholds, hooks |
| `failure-handling` | swallowing an error, adding a silent fallback or default, or special-casing an input |
| `outbound` | contacting a network host the code or the agent did not contact before |
| `authority` | authentication, authorisation, secrets, permissions |
| `deletion` | deleting data or files that are not regenerated by the build |
| `territory` | touching files outside the commission's territory |
| `scope` | doing materially more, less or other than the commissioned goal |
| `behaviour` | a user-visible behaviour the goal left open (defaults, error handling, limits, ordering) |
| `structure` | internal design: module boundaries, patterns, naming, where state lives |
| `other` | none of the above |

`test-strength`, `type-strength`, `guardrail`, `failure-handling`, `authority` and `deletion` are **guarantee categories**. A decision in a guarantee category is never a question of fact (§5) and is outside every writ (§9), so it reaches the human even when the agent declared it. An agent's disclosure does not clear a flag; only a ruling does.

`failure-handling` is here because measured agent behaviour puts it ahead of test weakening: bending the code to satisfy a wrong test, or adding a quiet fallback, is the more common shortcut (`../research/1_detection.md`, implication 4).

## 5. Fact and will *(later, defined now because M3 records the inputs)*

A decision is a **question of fact** only if all three hold:

1. a check exists that runs in the world, is deterministic, and whose result selects one option;
2. the check was written without sight of the agent's chosen option, or existed before the commission;
3. the decision is not in a guarantee category.

Every other decision is a **question of will**. The default is will. A clerk that cannot show the check for condition 1 may not label a decision fact.

Mechanical checks are preferred to model review wherever both could settle a fact (Dawes, Faust and Meehl 1989). A sample of decisions settled as fact is shown to the human, and the share the human says should have been theirs is the **false-fact rate** (`00` §4, C14).

## 6. States

```
            declare / detect                    rule
  (none) ─────────────────────▶ open ──────────────────────▶ ruled
     │                            │  agent acts on an option     ▲
     │ expect                     ▼                               │ rule
     ▼                         assumed ───────────────────────────┘
  expected ──matched──▶ (merges into the matching decision)
     │
     └──commission ends unmatched──▶ unanswered

  open | assumed ──premise gone──▶ moot
```

- A decision is **open** when it is known and nobody has acted on it.
- It is **assumed** when a commit in its world rests on a chosen option and no ruling exists.
- It is **ruled** when a ruling is recorded. A ruling for the chosen option ratifies the assumption. A ruling for another option is an **overrule** *(rollback: later)*.
- It is **moot** when its world is discarded or the files it concerns are reverted.
- An expected decision that never matches is **unanswered** when the commission ends.

A ruling may be given on an expected decision before any agent has met it (the upfront hearing, M2.5). A later declared or detected decision that matches it (§7.1) inherits that ruling and is `ruled` from the start, unless it is in a guarantee category, which always gets its own ruling.

Only these transitions exist. A ruled decision never changes state; a later ruling on the same question is a new decision citing the old one.

## 7. Reconciliation

Three sources feed the ledger: **declared** (the agent called `record_decision` or `petition`), **detected** (a detector fired, `03`), **expected** (the backbrief lists, M2).

### 7.1 Matching

Two entries **match** when they have the same `category` and either

- their `paths` overlap (one path equals, contains, or is matched by a glob in the other), or
- at least one of them has empty `paths`, and no other entry of that category with overlapping paths exists in the same world.

`other` never matches `other` by category alone; it needs overlapping paths.

Matching is evaluated per world, at every observed commit, over all entries of that commission up to that commit. Matched entries merge into one decision whose `sources` is the union.

### 7.2 Verdicts

| `recon` | Sources | Meaning | Goes to |
|---|---|---|---|
| `confirmed` | declared + detected | The agent said so and the work shows it | Ledger only |
| `declared-only` | declared | Said, with no detector evidence. Normal for `behaviour` and `structure` | Ledger only |
| `undeclared` | detected, no declaration at or before the commit that triggered the detector | **The agent decided without saying** | The clerk *(later)*; in M3, the report |
| `late` | detected first, declared in a later commit | Said only after being caught, or after the fact | As `undeclared`, marked late |
| `unanswered` | expected only, at commission end | A decision everyone foresaw left no trace | The clerk *(later)*; in M3, the report |
| `unforeseen` | declared or detected, not expected | Neither list predicted it. Measures backbrief quality | Ledger only |

`undeclared` and `unanswered` are the two verdicts the rest of Court exists to act on. `unforeseen` combines with any of the first four.

### 7.3 What reaches the queue

A decision is **queued** when any of these holds; otherwise it stays in the ledger only.

1. `recon` is `undeclared`, `late` or `unanswered`.
2. It is marked `outside-writ` (§9), which includes every guarantee category.
3. The agent declared it with `petition: true`.
4. It is contested (§7.5).

Most detector hits are legitimate changes (`../research/1_detection.md`, implication 2: about 4% of held test changes were unexplained weakening). Reconciliation is therefore the precision filter: a hit the agent declared, inside its writ, is recorded and not queued. A queued item is a question, never an accusation.

### 7.4 Timing

The declaration window for a commit closes when Court observes the commit. A declaration recorded after that is `late` for every detector hit in that commit. There is no grace period: an agent that intends to declare can do so before committing.

### 7.5 Contests between worlds

Parallel agents each make choices the others never see, and the results do not fit together. Court compares decisions across the worlds of one commission.

Two decisions in different worlds are **contested** when they match under §7.1 and their evidence differs: the detector hits do not have identical text digests, or one has a hit and the other only a declaration. Two worlds that made the identical change are in agreement, not in contest.

A contest is recorded as `decision.contested` naming both decisions, and is queued as one item. It is evaluated at every observed commit, so it is raised before either world is merged. Court does not judge whether the two choices are compatible; it asks.

## 8. Reversibility class

| Class | Definition in version 1 |
|---|---|
| `reversible` | Every effect of acting on the option is confined to the world's git state, and nothing has left the machine |
| `irreversible` | Anything else: a network write, a push, a deployment, a deletion outside the world, a message sent |

Reversibility is demonstrated, not declared (Gray 1981; Garcia-Molina and Salem 1987). A world is treated as reversible only because M1.3 proves, on every check run, that discarding a world restores the repository bit for bit.

Version 1 has no compensable class. Agents run with outward actions denied by the agent tool's own permission system (`02` §4), so an irreversible decision can only arrive as a petition.

## 9. Writs

```yaml
writ:
  agent:       id
  parent:      id of the issuing agent, or "human"
  categories:  [categories the agent may decide alone]
  class:       reversible                    # version 1: no agent may decide an irreversible question alone
  territory:   [path globs]
  budgets:     {tokens, minutes, speculation}
```

**Attenuation.** For a writ W issued by parent P: `W.categories ⊆ P.categories`, every glob in `W.territory` is contained in `P.territory`, and every budget in W is at most the parent's remaining budget. A writ that breaks this is refused at issue, and the refusal is recorded.

A declared or detected decision whose category or paths fall outside its agent's writ is marked `outside-writ`. Guarantee categories are outside every writ in version 1.

## 10. Assumptions and cost of delay *(later; recorded from M3)*

- A commit **rests on** assumption D when D is `assumed` in that world at the time of the commit and D's first commit is an ancestor of, or is, this commit.
- Court records the ids as `assumes` on each `world.commit` event. Agents do not write them.
- **Cost of delay** of an unruled decision is computed by Court from the ledger: the number of commits, changed lines and agent-minutes resting on it. Agents never state urgency or cost. A claimed urgency is a costless message from an interested party (Crawford and Sobel 1982), and would let an agent buy the human's attention.
- **Speculation debt** of a world is the total changed lines resting on unruled assumptions. Its cap is a budget in the writ.
- **The fallback belongs to the human.** For a decision outside its agent's writ, what holds while no ruling exists is the state before the change, never the agent's choice. An agenda setter's power grows with how bad the fallback is for the chooser (Romer and Rosenthal 1978); if the agent's own choice were the fallback, every unruled decision would go the agent's way.

## 11. The ledger

### 11.1 Envelope

```json
{"seq": 41, "prev": "<sha256 hex of event 40>", "at": "2026-11-15T14:03:22.418Z",
 "commission": "C7", "actor": "court|human|agent:<id>|clerk", "type": "<§11.2>", "body": {}}
```

- One ledger per Court data directory. `seq` starts at 0 and has no gaps.
- `prev` is the SHA-256 of the previous event's canonical bytes (RFC 8785). Event 0 has `prev` of 64 zeros.
- Events are immutable. A correction is a new event.
- The chain detects corruption and out-of-band edits. It is not a signature: version 1 makes no claim against an attacker who can rewrite the whole file. Signatures arrive with human rulings *(later)*.

### 11.2 Event types in M1 to M3

| Type | Actor | Body |
|---|---|---|
| `commission.opened` | human | goal, done-checks, territory, budgets, which values were defaults, the exemption list in force |
| `commission.closed` | court | outcome, counts by `recon` |
| `agent.started` | court | agent id, parent, tool and version, world, writ id |
| `agent.stopped` | court | agent id, reason |
| `tool.event` | agent | tool name, input digest, selected input fields (§11.3), outcome (`ok`, `error`, `denied` with reason) |
| `world.created` / `world.discarded` | court | world id, base commit, branch |
| `world.commit` | court | world, commit id, parent ids, changed paths with line counts, `gated: bool`, `assumes` |
| `backbrief.submitted` | agent or clerk | restated goal, plan, expected decisions `[{question, category, paths, intended_default}]` |
| `writ.issued` / `writ.refused` | court | the writ, or the violated rule |
| `decision.declared` | agent | question, category, paths, options, chosen, `petition: bool` |
| `decision.none` | agent | the agent's statement that its next commit contains no decisions (`no_decisions`) |
| `decision.detected` | court | detector id, category, paths, commit, the matched evidence (file, line range) |
| `decision.phrased` | clerk | decision id, question, alternative not taken |
| `decision.reconciled` | court | decision id, sources, `recon`, flags (`late`, `unforeseen`, `outside-writ`) |
| `decision.contested` | court | the two decision ids, their worlds, the differing evidence |
| `decision.ruled` | human | decision id, option |
| `claim.done` | agent | task, the done-check ids it asserts pass |
| `claim.checked` | court | claim, each done-check's actual result, `unverified-by-agent: bool` |
| `alarm.raised` | agent | text, paths |

### 11.3 What is stored from tool events

Tool inputs can be large and can contain secrets. A `tool.event` stores the tool name, a SHA-256 of the full input, the outcome (ok, error, denied), and only these input fields: file paths, command line (first 500 characters), and host names. File contents and command output are not stored.

### 11.4 Replay

`court replay <ledger>` rebuilds every decision, state and verdict from the events alone and compares them with the stored `decision.reconciled` events. Any difference is an error. This is the check that §2 holds.
